6

Open questions for the owner

  1. Desktop V2 labels its step 3 gate "Hard gate" yet offers "Always for prisma migrate here". Under the rule in this brief, a hard gate never offers it. I drew prisma migrate as an ordinary gate and used a delete outside the project as the hard gate. Which classification is right, and which surface changes?
  2. Can a person choose Always here outside watch? The approve command has no way to say it. I left it interactive only rather than invent a flag.
  3. A script calling approve on a hard gate is refused with 33, so a script can never be the person. Deny works from anywhere. Is a terminal attached to stdin enough proof of a person, or does a hard gate need a device credential with a decide scope as well?
  4. When does send land: when the current tool call returns (drawn), or at the next turn boundary like a model change?
  5. Does watch exit when the turn ends (drawn), or keep following later turns?
  6. Reconnect attempts and backoff are not specified anywhere. I drew five attempts, doubling from 2s. The daemon side is also open: how long does it keep a result for a client that has not come back?
  7. The receipt line "checkpoint ckpt_7f24 taken before it ran" depends on the per-approval checkpoint, which Desktop V2 marks as proposed. Drop the line until it ships?
  8. Both layouts use · − … and B uses box drawing characters. What does the CLI print when the locale is not UTF-8, and is NO_COLOR honoured? Layout A survives both because every state is also a word.
  9. The policy refusal says only an org owner can change the rule. Should it also name where, and does a solo account have an owner?
  10. The exit code numbers are proposed. Which are frozen for 1.0, and is 130 right for Ctrl-C when the session keeps running?
