The refusal card takes focus only while the person is still where the refused start left them: the document, the loading line its code loaded behind, or the Domovoi control that opened the start. The loading line and the start controls (the New session buttons, the palette's New session row, the launcher's submit and the fork controls) are known by the exact nodes their components registered, not by any attribute, so nothing a page draws can claim either place. It waits while focus is still in the closing launcher. Focus anywhere else stays where it is: a text field, a select, an editable region, a frame, an open shadow host or custom element whether registered or not, any unregistered control, another dialog, and any element inside a shadow root. A host whose closed root may hold a field keeps focus whatever its tabindex or attributes. The card judges the element that holds focus inside open shadow roots, not only their outermost host. Dialog membership follows the composed tree through assigned slots, so a control slotted into a dialog drawn in a shadow root counts as inside that dialog, both for the control the shell records a start came from and for the card's wait on the dialog the start was made in.
